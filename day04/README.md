# Day 04｜資源清單空白，就代表主機被刪除了嗎？

## 題目情境

在 AWS 管理介面（Console）查看 EC2 主機時，選擇哪個 Region，清單就會顯示部署在那個 Region 的主機。

IAM User（IAM 使用者）則是帳號中的全域身分，不會因為切換 Region，就在另一個 Region 產生新的使用者。

### 切換 Region 後，主機清單變成空白

同事在值班時查看 EC2 與 IAM，過程中都使用同一個 AWS 帳號與身分：

```text
09:00  查看 Tokyo（東京）Region 的 EC2 主機清單，可以看到 Web-01。
09:02  接著將右上角的 Region 切換為 Singapore（新加坡），EC2 主機清單變成空白。
09:03  開啟 IAM，仍看得到原本的使用者。
```

紀錄期間沒有人新增、搬移或刪除資源，目前身分的權限正常；兩次查看 EC2 時，都沒有套用搜尋條件。

**根據這份紀錄，EC2 清單變成空白，是否能認定 Web-01 被刪除呢？**

---

## 第 1 題－切換 Region 會改變什麼（複選）

同事只在 Console 右上角切換 Region，沒有進行任何資源操作。以下哪兩項敘述正確？

A. 切換到哪個 Region，EC2 清單就會顯示部署在那個 Region 的主機。
B. 原本 Region 的 EC2 主機會跟著出現在新 Region 的清單中。
C. IAM User 是全域身分，切換 Region 不會在新 Region 另外建立一個相同的使用者。
D. 原本 Region 中的資源會因為這次切換而停止計費。
E. 切換 Region 就等於切換到另一個 AWS 帳號。

### 答案

**A、C**

### 理由

EC2 是依 Region 查看資源，因此切換 Region 後，看到的是新 Region 的 EC2 清單。

IAM User 則是 AWS 帳號中的全域身分，不會因為切換 Region 而產生另一個使用者。

---

## 第 2 題－如何記錄清單空白的情況（單選）

根據這份值班紀錄，以下哪一句適合寫在交接紀錄中，說明目前看到的情況？

A. 目前只確認新加坡 Region 的 EC2 清單是空的，要查看 Web-01，應切回東京 Region。
B. IAM 使用者仍然存在，代表 EC2 主機也應該同時顯示在每個 Region 的清單中。
C. 切換到新加坡 Region 後，Web-01 已暫時移到該區，只是清單還沒更新。
D. 新加坡 Region 的 EC2 清單空白，代表目前使用的身分沒有查看該區 EC2 的權限。

### 答案

**A**

### 理由

Web-01 原本部署在東京 Region，而目前查看的是新加坡 Region，因此清單沒有顯示 Web-01 是正常的。

目前只能確認新加坡的 EC2 清單是空的，不能因此推論 Web-01 已被刪除。

### 這題要記住

**看到資源清單是空的，要先確認目前查看的是哪個 Region。**

---

## 第 3 題－切回東京後仍找不到 Web-01（單選）

接著，同事將 Region 切回東京，但 EC2 清單仍沒有顯示 Web-01。這次清單套用了 **`Name=DB` 的搜尋條件**，期間依然沒有資源變更，權限也正常。

若要查看 Web-01，最直接的下一步是什麼？

A. 重新建立一台 Web-01，因為兩次查看清單都沒有列出它。
B. 改用另一個有 EC2 權限的 IAM User 登入，再查看一次清單。
C. 清除搜尋條件，或改成符合 Web-01 名稱的條件，再查看清單。
D. 將 Region 改回新加坡，就可以透過搜尋條件找到東京的主機。

### 答案

**C**

### 理由

現在已經切回 Web-01 所在的東京 Region，但清單套用了 `Name=DB` 的搜尋條件。

如果 Web-01 不符合這個條件，就不會出現在結果中，因此應先清除搜尋條件或修改成符合 Web-01 的條件。

### 這題要記住

**清單沒看到資源，不代表資源不存在，也可能是 Region 或搜尋條件不正確。**
