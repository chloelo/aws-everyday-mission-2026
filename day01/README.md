# Day 01｜選擇 Region 前，思考這份部署提案還缺少什麼？

## 題目情境

### 先認識 Region

AWS Region 是部署 AWS 資源的地理區域。不同 Region 支援的服務與費用可能不同，因此選擇 Region 時，除了使用者的位置，也要考量服務支援、預算、資料放置要求及連線延遲。

其中，在評估連線延遲時，使用者與 Region 的距離可以作為初步參考，但距離較近不代表實際連線一定比較快。若要比較不同 Region 的使用者體驗，仍需要參考從使用者所在地測得的延遲結果。

### 收到一份 LiveFit 的部署提案

LiveFit 第一版預計提供東京會員使用，目前正在評估部署要選擇哪個 Region。以下是產品負責人提出的需求，以及同事目前的評估與建議。

> **產品負責人：** 會員登入後，系統會寄出驗證信，會員開啟頁面時的反應速度也很重要。至於資料放置，公司要求資料必須留在日本。
>
> **同事：** 目前有兩個候選 Region，我已確認兩者都符合公司的資料放置要求，預估費用也都在預算內。考量到會員主要在東京，我想直接選擇 Tokyo（東京）Region。

關於產品負責人提到的驗證信，團隊已經選定寄信服務，這次規劃部署時會使用這項服務，所以不再更動。

提案所附的四份資料如下：

1. 費用估算表
2. 資料放置確認書
3. 候選 Region 的 AZ 數量表
4. 兩台測試主機彼此連線的結果

附件④只記錄兩台測試主機彼此連線的結果。

---

## 第 1 題－如何看待部署需求（單選）

企劃整理前述部署需求時，列出「資料必須留在日本」與「希望頁面回應快」這兩項要求。選擇 Region 時，應如何看待這兩項要求？

A. 這兩項都屬於團隊偏好，可以和預估費用一起考量，不一定都要做到。

B. 資料留在日本是必須符合的要求；頁面回應速度則需要透過使用者的連線測試來評估。

C. 兩個候選 Region 都在日本，可以認為會員連線時的延遲差不多，不需要另外測試。

D. 只要看附件③列出的 AZ 數量，就能確認是否符合資料放置要求，以及會員連線時的延遲表現。

### 答案

**B**

### 理由

「資料必須留在日本」是公司明確要求的必要條件，不能當成偏好取捨。

頁面回應速度則不能只用 Region 距離判斷，需要透過實際連線測試確認延遲。

---

## 第 2 題－提案還缺少哪些資訊（複選）

在這份部署提案通過前，請協助看看以下哪兩個項目資訊是附件沒有提供、也無法從現有附件得知的？

A. 團隊選定的寄信服務在兩個候選 Region 的支援狀態。

B. 兩個候選 Region 各自的每月費用估算。

C. 東京會員分別連到兩個候選 Region 的延遲測試結果。

D. 兩個候選 Region 各有幾個 AZ。

E. 兩個候選 Region 是否符合公司的資料放置要求。

### 答案

**A、C**

### 理由

附件①～③已經分別提供費用、AZ 數量及資料放置資訊。

附件④雖然有連線測試，但測的是**兩台測試主機彼此之間的連線**，不是東京會員連到兩個候選 Region 的實際延遲。

另外，團隊已選定寄信服務，但目前資料沒有說明該服務在兩個候選 Region 是否支援。

---

## 第 3 題－根據測試結果選擇 Region（單選）

提案後續有再補上一些資料，是關於兩個候選 Region 的比較結果。下方表格的延遲來自東京會員實際連線情況的測試。

| 候選 Region | 資料放置要求 | 所選服務 | 預估月費  | 東京會員連線延遲 |
| --------- | ------ | ---- | ----- | -------- |
| Tokyo（東京） | 符合     | 支援   | US$24 | 18ms     |
| Osaka（大阪） | 符合     | 支援   | US$20 | 34ms     |

這次的選擇規則是：先確認方案符合必要條件，且預估月費不超過 US$30，再從符合條件的方案中選擇實測延遲較低的 Region。

根據這個規則，以下哪一項選擇與理由正確？

A. 選 Osaka（大阪），因為兩個方案都符合條件，接著應選擇月費較低的 US$20 方案。

B. 暫時不選，因為兩者的延遲只差 16ms，還不足以判斷應選哪個 Region。

C. 選 Tokyo（東京），因為兩個方案都符合條件，而東京的實測延遲 18ms 低於大阪的 34ms。

D. 選 Tokyo（東京），因為它離會員最近，不需要再看延遲測試結果。

### 答案

**C**

### 理由

兩個 Region 都符合資料放置要求、服務支援及 US$30 的預算上限，因此都進入比較範圍。

題目最後指定要比較**實測延遲**，東京為 18ms、低於大阪的 34ms，所以選擇 Tokyo。

### 這題要記住

Region 選擇不能只看地理距離或價格，要先確認必要條件，再依題目指定的評估條件比較。
